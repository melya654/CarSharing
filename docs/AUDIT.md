# Аудит: Lighthouse, тестування, доступність

## Lighthouse (mobile, Slow 4G, симуляція)

«До» це dev-сервер Vite (`npm run dev`): код без мініфікації, React у режимі розробки, кожен модуль окремим запитом.
«Після» це production-збірка (`npm run build` + `npm run preview`) з усіма оптимізаціями нижче.
HTML-звіти лежать у `docs/lighthouse/`.

INP Lighthouse в лабораторному режимі не міряє (для нього потрібні реальні кліки користувачів), тому замість нього дивився TBT. Він показує, наскільки головний потік зайнятий і чи буде сторінка гальмувати на кліки.

## Що оптимізував

1. Production-збірка Vite: мініфікація JS і CSS, React без dev-перевірок.
2. Code splitting: усі сторінки, крім головної, вантажаться через `React.lazy` окремими файлами (Catalog 3 KB, Compare 2.4 KB і т.д.).
3. Зображення у WebP, у кожного `<img>` задані `width` і `height`, щоб не було стрибків, у карток `loading="lazy"`, у hero `fetchpriority="high"`.
4. `main { min-height: 100vh }`: футер більше не стрибає, поки вантажиться каталог (CLS каталогу був 0.162, став 0).
5. Контраст: білий текст на помаранчевій кнопці в темній темі давав 2.6:1, зробив текст темним (7.9:1).
6. Порядок заголовків: у каталозі після h1 одразу йшли h3 карток, додав прихований h2 «Результати пошуку».
7. Перемикач теми: у кнопки був aria-label, що не збігався з видимим текстом. Прибрав aria-label, тепер видимий текст «Світла тема».
8. SEO: унікальні title і description для кожного маршруту (хук `useTitle`), `robots.txt`, `sitemap.xml`, JSON-LD `Product` на сторінці авто.

## Доступність (перевірка з клавіатури)

- Перший Tab фокусує посилання «Перейти до вмісту».
- По всіх сторінках можна пройти лише Tab / Shift+Tab / Enter, фокус видно (обведення 2px кольором primary).
- Модалка: фокус переходить на кнопку «Закрити», закривається по Esc і кліку поза вікном, після закриття фокус повертається.
- Бургер-меню має `aria-expanded` і `aria-controls`.
- Помилки полів прив'язані через `aria-describedby`, поле з помилкою має `aria-invalid="true"`.
- Таблиця порівняння: `th scope="col"` / `scope="row"`, найкраще значення продубльоване прихованим текстом «(найкраще)», бо колір екранний читач не бачить.

Lighthouse Accessibility на всіх сторінках 100. Перевірку axe DevTools треба ще прогнати в браузері (розширення), Lighthouse використовує той самий рушій axe-core.

## Знайдені баги (оформити як GitHub Issues)

1. На 360 px сторінка порівняння мала горизонтальну прокрутку 493 px. Причина: прихований текст `.sr-only` з `position: absolute` вилазив за межі таблиці. Виправлено: `position: relative` у `.table-wrap`.
2. Панель «Обрано для порівняння» показувалась і на самій сторінці порівняння, де вона не потрібна. Виправлено перевіркою `pathname`.
3. Низький контраст тексту на кнопці primary у темній темі (2.6:1). Виправлено.
4. У каталозі пропуск рівня заголовка (h1 → h3). Виправлено.
5. CLS 0.162 у каталозі через футер. Виправлено.
6. W3C-валідатор (vnu.jar, той самий рушій, що на validator.w3.org) на сторінці контактів: `h2` всередині `address` і `width="100%"` в iframe. Виправлено, тепер 0 помилок на всіх 6 сторінках.
